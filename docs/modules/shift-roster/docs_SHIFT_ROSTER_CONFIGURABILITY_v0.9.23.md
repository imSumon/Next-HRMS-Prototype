# Shift & Roster configurability — v0.9.23\n\n## Implemented in this prototype\n- Company-specific assignment method: Employee-based, Roster / Calendar-based, Hybrid with approval.\n- Company-specific approval required toggle.\n- Company-specific future roster visibility preference.\n- Weekly-off day selection saved as policy configuration.\n- Roster lifecycle: Draft → Pending Approval → Published when approval is required; Draft → Published can be used by authorized HR when approval is disabled.\n- Approval records submitter, approver and timestamps. Existing Published-date conflicts are skipped.\n- New roster rows retain a shift timing snapshot (name, start, end, break, late/early grace) so later Shift Master edits do not change the stored roster timing.\n\n## Important limitations (not claimed as complete)\n- Employee-based, roster-based and hybrid policy choices are saved, but full attendance schedule-resolution enforcement is not connected to an attendance calculation engine yet.\n- Default shift is not yet editable in Employee Profile. Existing Employee Shift Assignment is the available effective-dated assignment workflow.\n- Weekly-off configuration is stored but does not automatically generate Off roster rows.\n- Full month calendar grid, recurring/rotating roster generator, department/branch/group scheduling, temporary/permanent change requests, approval delegation/levels, immutable audit backend and durable server-side authorization are not implemented.\n- Browser-local prototype only; not a live multi-tenant backend.\n
